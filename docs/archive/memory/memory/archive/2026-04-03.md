## OpenRouter Tool Calling Fix (CRITICAL)

**Problem:** Calendar skill wasn't working - LLM was returning text instead of tool_use blocks, then tool results caused "empty content" errors.

**Root Cause:** `OpenRouterAdapter.build_request()` was stripping `tool_calls` and `tool_call_id` from messages:
```python
# BROKEN - only kept role and content
msgs.extend([{'role': msg['role'], 'content': msg['content']} for msg in messages])
```

**Fix:** Preserve all message fields:
```python
for msg in messages:
    new_msg = {'role': msg['role'], 'content': msg.get('content')}
    if msg.get('tool_calls'):
        new_msg['tool_calls'] = msg['tool_calls']
    if msg.get('tool_call_id'):
        new_msg['tool_call_id'] = msg['tool_call_id']
    msgs.append(new_msg)
```

**Proper OpenRouter Tool Format:**
1. Assistant message: `{"role": "assistant", "content": null, "tool_calls": [...]}`
2. Tool result: `{"role": "tool", "tool_call_id": "...", "content": "..."}`
3. Include `tools` in both request passes
